# ADR 0025: FRITZ!Box built-in WireGuard for admin access from outside

- Status: Accepted
- Date: 2026-09-26
- Supersedes: [ADR 0024](0024-wireguard-admin-vpn.md)
- Deployment status: live since 2026-09-26, first device (Linux laptop) confirmed: tunnel from outside the LAN, then SSH to the homeserver

## Context

ADR 0024 put a WireGuard server on the homeserver as an Ansible role.
It was merged and applied on the same day. Reviewing it again, the
FRITZ!Box's built-in WireGuard (Internet → Freigaben → VPN (WireGuard))
turned out to fit better. ADR 0024 had dismissed it too quickly,
treating "config not in Git" as a conflict with the IaC-only rule.
That rule is about not bypassing an existing IaC path. The FRITZ!Box
has no IaC path at all, and its port forwards and DynDNS are already
manual, documented settings.

## Decision

Use the **FRITZ!Box's built-in WireGuard** for admin access from
outside, one "Geräteverbindung" per client device, set up as a manual,
documented step ([runbook](../runbooks/fritzbox-wireguard-vpn.md)).
The homeserver role from ADR 0024 is torn down (`home-infra#70`).

Why this over ADR 0024:

- **Nothing new on the homeserver's network stack.** No `ip_forward`,
  FORWARD or MASQUERADE rules next to Docker, libvirt and the k3s DNAT,
  where the hairpin and ghcr.io bugs already happened.
- **It keeps working when the homeserver doesn't.** During a freeze the
  LAN and the FRITZ!Box itself stay reachable.
- **No port forward, nothing to maintain.** The FRITZ!Box terminates
  WireGuard itself and hands each device a QR code or config file.
- **Simple model:** a connected device behaves as if it were at home.

Public web services stay on Traefik + Authelia, as before.

## Consequences

- The VPN config lives only in the FRITZ!Box. It is covered by the
  FRITZ!Box's own settings export, and the runbook describes how to
  recreate it. Nothing in Git detects drift.
- The k3s network (`192.168.101.0/24`) is not directly reachable from
  VPN clients, the same as from the LAN today. Reach it through the
  homeserver (SSH, SSH tunnel).
- Client keys are generated by the FRITZ!Box, not on the device.
- Clients get the FRITZ!Box as DNS by default. Change it to Blocky
  (`192.168.178.100`) in the client config to keep ad-blocking on the
  road.
- `vpn.jkandler.de` (`aws/dyndns#42`, built for ADR 0024) stays as a
  readable endpoint alias for `jkandler.de`.
